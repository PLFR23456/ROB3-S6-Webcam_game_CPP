Detailed Description

Point d'entrée principal de l'application de suivi de couleur.

Ce fichier contient la fonction main qui initialise et coordonne les différents composants de l'application : le traitement vidéo en temps réel et l'interface utilisateur graphique.

L'application fonctionne avec une architecture multi-thread :

  • Thread principal : Interface graphique (SFML) et gestion des événements
  • Thread secondaire : Traitement vidéo (OpenCV) et détection de couleur

int main ( )

Fonction principale de l'application.

Point d'entrée du programme qui :

  1. Initialise la session de jeu avec les positions par défaut
  2. Lance le thread de traitement vidéo (camera)
  3. Démarre l'interface graphique (display) dans le thread principal
  4. Attend la fin du thread de traitement vidéo avant de terminer

Architecture multi-thread :

  • Thread principal : Interface utilisateur SFML
    • Gestion des événements utilisateur (clics, fermeture)
    • Rendu graphique (flux vidéo, labyrinthes, interface)
    • Contrôle du flux de jeu
  • Thread secondaire : Traitement vidéo OpenCV
    • Capture depuis la webcam
    • Détection et suivi de couleur
    • Calcul de la position du marqueur
    • Détection des collisions avec les murs
Note
La synchronisation entre threads se fait via :
  • Variables globales partagées (startbox, endbox, game)
  • Mutex pour l'accès aux données de traitement vidéo
  • Signal atomique stop_signal pour l'arrêt coordonné
Warning
Le programme doit être fermé proprement via l'interface pour éviter les fuites de ressources et assurer la terminaison correcte des threads

Thread dédié au traitement de l'image

Ce thread exécute la fonction camera() qui gère :

  • L'acquisition vidéo depuis la webcam
  • La détection de couleur en temps réel
  • Le calcul de position du marqueur coloré
  • La détection des collisions avec les éléments du jeu

Le thread fonctionne en boucle continue jusqu'à réception du signal d'arrêt stop_signal.

Interface graphique principale

La fonction display() s'exécute dans le thread principal et gère :

  • La fenêtre SFML et les événements utilisateur
  • L'affichage du flux vidéo traité
  • Le rendu des éléments de jeu (labyrinthes, zones)
  • L'interface utilisateur (boutons, score, paramètres)

Cette fonction est bloquante et retourne seulement quand l'utilisateur ferme l'application.

Attente de la fin du thread de traitement

Avant de terminer le programme, on s'assure que le thread de traitement vidéo se termine proprement. Cela évite :

  • Les fuites de ressources (caméra, mémoire)
  • La terminaison brutale du processus
  • Les erreurs de segmentation potentielles
